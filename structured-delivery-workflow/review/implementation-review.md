# Implementation Review

Read the [review policy](policy.md), then adversarially review delivered
behavior. Inputs include the plan and implementation commits or diff range,
spec, task map, all tasks, promoted artifacts, and required validation.

Trace every requirement, acceptance criterion, and applicable user correction
to observable behavior and credible tests across affected peers. Inspect code,
tests, git state, and cheap non-mutating checks; recorded commands are claims,
not proof. Requirements remain authoritative.

Challenge significant decisions and assumptions against implementation
evidence, then check task completion, dependencies, and promoted knowledge.
Apply the shared [documentation](../../AGENTS.md#documentation) and
[verification and cleanup](../../AGENTS.md#test-and-clean-up) policies to
changed artifacts.

Order material defects by delivery risk.
