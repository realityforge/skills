# Planning Review

Read the [review policy](policy.md), then adversarially review `SPEC.md`,
`TASKMAP.md`, and every task as one delivery unit.

Test the plan against accepted outcomes, constraints, authority, checkpoints,
user corrections, and repository evidence. Seek material omissions, invalid
assumptions, unnecessary complexity, unsafe sequencing, consequential impacts
absent from decisions, and validation that could falsely pass. Check that every
requirement and acceptance criterion has verifiable task ownership, including
migration, rollout, tests, documentation, and cleanup.

Report only defects that threaten correct delivery or cause material rework.
